# 詳しい使い方

インストールの手順は [トップページの日本語ガイド](../README.md) をご覧ください。

## 論文を取り込む

⌘Pでコマンドパレットを開き、「Zotero Paper Import: Zoteroから論文を取り込む」を選びます。左リボンのダウンロードアイコンでも開けます。

タイトル・著者・年で検索し、論文をクリックすると待ち行列に追加します。続けて論文を選べます。選択画面を閉じてもバックグラウンドで1本ずつ命名し、次の形式で保存します。

```text
設定した親フォルダ/未整理/
└─ smith2025/
   ├─ smith2025.md
   └─ 本文.pdf
```

PDF添付が複数ある場合は「確認待ち」になります。「取り込み状況」から本文と一緒に保存する補足資料を選び、待ち行列の末尾へ戻して続行します。補足資料は別名で同じフォルダに保存します。PDFのダウンロードを確認できない場合は理由を表示し、「ノートだけ保存」を選べます。後からZoteroでPDFを取得し、ノートを更新できます。

同じ論文を重複して待ち行列へ追加することはありません。既に取り込み済みの場合は、既存のノートを結果として表示します。完了時にノートを勝手に開くことはありません。ファイル名を比較するだけでなく、取り込み元のZoteroデータベース・ライブラリ・アイテムキーで照合します。同じデータベースからの取り込みは、保存先の設定変更や保管庫内の移動後も既存ノートを再利用します。

## 名前の設定

- **著者名＋年**：標準設定。AI不要です。Zoteroに記録された第一著者の姓と出版年を使います。年不明なら `nd`、著者不明ならアイテムキーを使います。
- **手法名**：AIが論文の提案手法・モデルの名前を確認します。比較対象や既存モデルを誤って採用しないよう指示し、判断根拠をノートに残します。
- **カスタムルール**：自分の言葉で命名ルールを書き、名前を付けて保存できます。複製・JSON形式での書き出し・読み込みに対応します。

AIが判断できない、または接続できない場合は、必ず著者名＋年で保存し、代替した理由を表示・記録します。手入力を求めることはありません。設定変更だけで既存フォルダは改名されません。既存ノートを開いて「現在の命名設定で改名」コマンドを明示的に実行した場合に適用します。

Zoteroに記録された書誌情報が誤っていれば、AI不要の命名もその情報に従います。必要なら先にZotero側を修正してください。保管庫側の名前はZoteroの引用キーへ書き戻しません。

## AI CLIを使う場合

「AIの設定（命名・整理）」でCodex、Claude Code、OpenCode、Antigravity CLI（agy）を選択できます。OpenCodeとAntigravity CLIは実験的対応です。著者名＋年で取り込む場合も、AIを使った整理の設定ができます。

1. 選んだCLIをインストールし、ターミナルでログイン・モデル設定を済ませます。
2. 「検出済み」なら次へ進みます。見つからない場合だけ「再検出」が表示されます。必要なら実行ファイルの場所を指定します。
3. モデルを一覧から選び、「AI接続テスト」で動作を確認します。モデル名を入力する必要はありません。迷ったら「自動」を選んでください。

接続テストもモデルの利用枠を消費する場合があります。論文取り込み時は、書誌情報・抽出したPDF本文・命名ルールを選択したCLIへ渡します。整理時は論文ノート・PDFの抽出本文・分類先の説明・分類ルールを渡します。送信先・料金・利用上限はそのCLIで設定したサービスに従います。プラグイン自体はAPIキーを保存しません。

Codexは認証を再利用し、個人の設定・フック・MCPを読み込まないモードで動かします。モデルはCLIから取得した一覧で選べます。`--ignore-user-config` に対応した最近のCLIが必要です。Claude Codeではツール・MCP・フックを無効にした呼び出しを使います。OpenCodeではツールを許可しない専用エージェントを使います。Antigravity CLIは一時フォルダの専用エージェント（完了応答のfinishだけを許可し、MCP・スキル・プラグインを指定しない定義）を選び、planモードとサンドボックスを指定します。論文本文は標準入力で渡し、構造化された命名結果だけを採用します。認証とCLI側の履歴・設定はAntigravityが管理します。

Claude CodeはSonnet・Opus・Haikuを選べます。Antigravity CLIは `agy models`、OpenCodeはCLIのモデルカタログから選択肢を取得します。迷ったら「自動」のままで使えます。Antigravityの一覧が取得できない場合は、ターミナルで `agy` を開いてログインしてから「一覧を更新」を押してください。利用できるモデルはログイン先と契約によります。

本文抽出はプラグインに同梱しています。OCRは行いません。最大200ページ、約18万文字をページごとの抜粋として渡すため、スキャンや複雑な表では名前を確認できない場合があります。AIが誤る可能性は残るので、ノート内の根拠を確認できます。

## ノートとPDFを更新する

文献ノートを開いて「この論文の情報・PDFを更新」を実行すると、更新を待ち行列へ追加します。以前選んだPDFと書誌情報を取得し直します。改名コマンドも同じ待ち行列で順番に処理します。

自分のメモは `<!-- zpi:generated:start -->` と `<!-- zpi:generated:end -->` の**外側**に書いてください。マーカー内はテンプレートから再生成する範囲です。プロパティの `zpi` は取り込み対応とPDFの検証情報なので編集しないでください。

更新前のノートとPDFは、保管庫の設定フォルダ内 `plugins/zotero-paper-import/backups/` にバックアップします。自動削除しないため、不要になったものは利用者が整理してください。

保管庫側のPDFをiPadなどで編集した場合は上書きせず停止します。元のPDFがZoteroから削除された場合も、保管庫のコピーを勝手に削除しません。PDFの注釈を書き戻したり、両方の注釈を統合したりする機能はありません。

## iPadで読む

Macで作成したノートとPDFをiCloudなどで同期し、iPadにダウンロードしてから開きます。iPadでこのプラグインやAI CLIを動かす必要はありません。オフラインにした状態で、文献ノートのPDFリンクから開けるか確認してください。

プラグイン自体はクラウド同期を行わず、iPad側のダウンロード状態も制御しません。

## ベータ版の範囲

1回につき1論文、1PDFにつき128 MiBまでです。検索結果は最新100件まで表示するので、必要に応じて検索語を絞ってください。既にPDFを取り込んだ論文へ、新しく増えた補足資料を追加選択する画面は未実装です。

Mac以外の実機動作や、複数のデスクトップで異なるZoteroデータベースから同じ保管庫を更新する運用は未検証です。別データベースの同じキーは自動統合せず停止します。自動分類・AI要約・Zoteroへの書き込み・Zotero注釈の抽出は行いません。

## 待ち行列の操作

画面下部の「文献の取り込み状況」、選択画面の「取り込み状況を見る」、または同名のコマンドから一覧を開けます。待機中・処理中・確認待ち・完了・失敗を表示します。待機中やAI処理中はキャンセルできます。保存を開始した後の短い処理は、途中で壊れないよう完了まで進めます。

保存先・命名方式・モデル・ルールは追加時点の設定を使います。確認待ちや失敗した論文でほかの論文を止めません。PDFを選択したものや再試行したものは待ち行列の末尾へ入ります。待ち行列は端末ごとに保持し、再起動で中断したものは「再試行」で再開します。完了・キャンセル済みの履歴は一覧からまとめて消せます。

## 取り込み済みの非表示

保存先以下にあるノートの `zotero-key` を照合して、取り込み済み論文を検索一覧から除外します。従来のZotlitノートにも対応します。`zotero-library` やZotero選択リンクがある場合はライブラリも照合します。ライブラリ情報のない旧ノートはマイライブラリとして扱い、グループの同じキーとは照合しません。`zpi` プロパティ付きノートは保管庫全体でデータベース・ライブラリ・キーを照合するため、手動で移動しても識別できます。

取り込みが完了した論文は、開いている選択画面からも消えます。待機中・処理中の論文は状態を表示します。ノートを外部から追加・削除した場合は検索し直すか画面を開き直すと反映されます。既存ノートへの更新はノートを開いて「この論文の情報・PDFを更新」を使ってください。この更新コマンドは本プラグインの `zpi` プロパティがあるノート向けです。

## CLIが入っていない場合

AIを選択すると、実行ファイルを自動で探します。「見つかりません」と表示されたら、その直下に導入手順が開きます。

1. 自動選択されたOSを確認します。別のOSの手順も選べます。
2. Macはターミナル、Windowsは通常のPowerShellを開きます。
3. 「コマンドをコピー」を押し、開いたターミナルに貼り付けて実行します。
4. 初回ログインのコマンドを実行し、アカウントを接続します。
5. Obsidianに戻り「再検出」→「AI接続テスト」を押します。

WindowsのOpenCodeはScoopで導入する手順を表示します。Scoopがない場合の準備も同じ画面で案内します。Windows版Obsidianから直接呼び出すため、WSLではなくWindows側へ導入してください。Windowsの.cmd・.ps1は直接呼び出さず、ネイティブの.exeを探します。別の場所に入れた場合は「CLIの場所を指定」を開いて実行ファイルを指定できます。

インストールコマンドは表示・コピーのみです。プラグインが自動実行することはありません。

## 0.3.0の設定と整理結果

「文献の親フォルダ」を選ぶだけで、取り込み先と整理対象が同じ未整理フォルダに決まります。旧保存先は照合対象として保持し、既存ファイルは自動で移動しません。

「元に戻す」は廃止しました。整理結果から「分類先を変更」を押し、現在の論文の移動先を選べます。過去の内容を復元せず、現在のメモとPDFを維持します。起動時に旧版の取り消し処理を再実行することもありません。

「キーを補完」ではキー未設定の既存ノートを1件ずつ選び、DOI・arXiv IDをZoteroと照合します。識別子はノートのテキスト型プロパティに記入してください。候補が一意に決まる場合だけプロパティを補完し、本文はそのまま保持します。候補の競合や識別子の不足は画面に表示します。
