## 自動テストの範囲

`npm run check` で次を確認します。

- 論文フォルダ・ノート・PDFの作成と再取り込み時の重複防止。
- 手動移動後や保存先の設定変更後も既存ノートを再利用。
- 別論文で名前が衝突する場合の分離。
- 別のZoteroデータベースにある同じキーを勝手に統合しないこと。
- 更新時の自分のメモの保持。
- 保管庫側で編集されたPDFの上書き防止。
- ノート作成に失敗した場合の、今回作ったPDFコピーの片付け。
- PDF未取得のノートへ、後から更新でPDFを追加。
- 更新中のノート編集を保持し、今回のPDF更新だけを戻す処理。
- 不正なパス・ファイル名・長すぎる名前・著者や年の欠損への対応。
- AIの返答形式と命名根拠の確認。
- 接続許可の無効・非対応バージョン・接続元変更の判定。
- CLIへ文章を安全に渡し、時間切れとキャンセルを処理。

テストデータは架空です。個人の文献・PDF・認証情報を公開リポジトリに含めません。

## 知人に試してもらう順番

空の保管庫へ導入し、まず「著者名＋年」でPDF付き論文を1本取り込みます。ノートからPDFを開き、取り込み後に一覧から消え、画面を開き直しても表示されないことを確かめます。自分のメモを書いて更新し、メモが残ることを確認します。

その後、AI CLIを使う人は手法名での命名を試します。iPadで読む場合は同期・ダウンロードを終え、通信を切ってPDFリンクから開けるか確認してください。
